# Istrolid Reverse Engineering Research

This repository is for studying the original Istrolid Electron client. This document reflects static inspection of the locally recovered `app.asar`; it is **not** proof of a working rebuild or recovered server.

## Recovered artifacts
- Electron application metadata: `package.json` (version 0.1.0, main: `main.js`)
- Electron main process: `main.js` (generated by CoffeeScript 2.7.0)
- Electron preload: `preload.js`
- Renderer entry HTML: `game.html`
- Combined renderer source: `js/istrolid.cat.js` (~1.72 MB; 35,977 lines)
- Atlas metadata: `atlases/atlas.js`

The local ZIP of recovered sources is available separately in the analysis conversation, but the source files have **not yet been imported into this GitHub repository**.

## Preliminary architecture
`game.html` loads `js/istrolid.cat.js` and contains a `canvas#webGL` renderer. The concatenated JavaScript bundle preserves `//from src/... ` source-file boundary comments, making a future source split practical.

Known source markers:
- `src/maths.js` near line 1,407
- `src/hspace.js` near line 2,765
- `src/linky.js` near line 2,844
- `src/zjson.js` near line 2,979
- `src/protocol.js` near line 3,453
- `src/utils.js` near line 3,935
- `src/db.js` near line 4,184

Key gameplay/network types observed in the bundle:
- `Sim` near line 7,916 — simulation; behavior still needs detailed auditing
- `Particle` near line 10,794
- `ShipExplosion` near line 11,454
- `Unit` near line 11,919
- `Part` near line 13,076
- WebSocket construction near lines 22,161 and 22,222
- `BattleMode` near line 26,645

Electron package dependencies include `ws`, `mysql`, `request`, `electron`, and `node-sshclient`. A declared dependency alone does not prove its runtime usage.

## Study roadmap
1. Import recovered source files, retaining original bytes and a SHA-256 manifest.
2. Split the concatenated JS at `//from` markers into readable modules without changing behavior.
3. Map initialization and canvas rendering.
4. Trace `Sim`, `Unit`, `Part`, weapons, damage, and build constraints.
5. Map WebSocket protocol messages, serialization, authentication, and client/server responsibility.
6. Inventory missing data/assets and establish whether an offline/local simulation can run.
7. Create separately maintained refactors/tests; do not overwrite recovered originals.

## Cautions
- Recovered client sources are distinct from any original server implementation.
- Do not commit private tokens, credentials, player data, or the original binary executables.
- Third-party source/assets may have redistribution restrictions; confirm permission/license before public release.
